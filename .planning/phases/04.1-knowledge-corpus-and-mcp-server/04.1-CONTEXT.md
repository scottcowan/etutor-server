<decisions>
## Implementation Decisions

### Corpus Structure (CORPUS-01, CORPUS-02)

- **D-01:** Corpus follows the knowledgebase-template L0→L1→L2→L3 layer model, mapped to etutor content types:
  - **L0 raw:** catalog entries only (URL, author, date) — no full content stored
  - **L1 source:** full markdown of source material (transcripts, book passages, experiment guides)
  - **L2 summary:** condensed summary per source with curriculum tag frontmatter
  - **L3 wiki:** canonical topic pages — the "stable API" downstream agents and the tutor consume

- **D-02:** Four content types at L3:
  - **Topic pages** (`wiki/topics/<topic_id>.md`) — one page per `services/curriculum.py` topic ID
  - **People/POI pages** (`wiki/people/<slug>.md`) — historical figures, scientists, thinkers referenced across topics
  - **Source material** (`wiki/sources/<slug>.md`) — transcripts, essays, curated passages with topic tags
  - **Experiment pages** (`wiki/experiments/<slug>.md`) — step-by-step practical activities, age-gated

- **D-03:** Topic pages use H2 sections for level bands (not separate files):
  ```
  ## 100 — Introduction
  ## 200 — Developing
  ## 300 — Intermediate
  ## 400 — Advanced / University
  ## Sources
  ## Related Topics
  ## People
  ```

- **D-04:** Corpus directory structure:
  ```
  docs/corpus/
    raw/index.md          # L0 source catalog
    source/               # L1 full conversions
    summary/              # L2 summaries with frontmatter
    wiki/
      topics/             # L3 topic pages (1:1 with curriculum topic IDs)
      people/             # L3 people/POI pages
      sources/            # L3 source material pages
      experiments/        # L3 experiment pages
      index.md            # master index of all L3 pages
  ```

- **D-05:** `docs/wiki/source-material/` (existing) maps to `docs/corpus/wiki/sources/`. Migration: rename/move existing files.

### Content Gating

- **D-06:** Two independent gates on corpus content:
  1. **Safety gate (hard min_age)** — applies only to experiments with physical hazards. Expressed as `min_age: 10` in experiment frontmatter. Permissive: a child who has completed the prerequisites can access the experiment even if slightly under the age hint — this is a recommendation, not a hard block. Genuinely dangerous activities (strong acids, open flames, high voltage) use a higher threshold that cannot be overridden.
  2. **Depth gate (prereq-based)** — content depth at 100/200/300/400 level unlocks when the child has mastered the prerequisite topics, same as the existing curriculum system. Age is implicit in `year_groups` already; no separate age check on content depth.

- **D-07:** Experiment frontmatter schema:
  ```yaml
  topic_ids: [volcanic_reactions, acids_and_bases]
  min_age: 10              # recommendation, not hard block (except flagged_dangerous: true)
  flagged_dangerous: false # true = hard age gate, no override
  equipment: [vinegar, baking soda, container]
  safety_notes: "Perform over a sink or tray."
  level: 200
  ```

### Content Curation

- **D-08:** No disclaimer/rider language on historical or offensive content. Pedagogical approach: teach colonialism, historical language change, and cultural context as curriculum prerequisites first, then use primary sources in context. The `curation_note` field in source frontmatter records the relevant prerequisite topic IDs to surface as a refresher — not a warning label.

- **D-09:** Curation is AI-assisted via agent conversation. No approval workflow in the system — the folder structure is the gate. Content in `docs/corpus/wiki/` is considered published. Work-in-progress lives in `docs/corpus/source/` until promoted.

- **D-10:** Source material frontmatter schema:
  ```yaml
  title: "The Enduring Wisdom of Happiness in Slavery"
  type: video_essay           # video_essay | book_passage | article | experiment | lecture
  source_url: "https://..."   # optional
  author: "@markradulich"
  captured: 2026-07-29
  topic_ids: [manipulation, political_systems, surveillance, dissent]
  level: 300
  prerequisite_topics: []     # topics to surface as refreshers before this source
  curation_note: ""           # records prerequisite context, not a disclaimer
  ```

### MCP Server (CORPUS-03)

- **D-11:** MCP server runs as a standalone stdio process — a Python script registered in `.claude/settings.json`. Does not require the FastAPI server to be running. Standard MCP pattern for Claude Code.

- **D-12:** Local model / no-MCP path: If Gemma 4 12B or another model without native MCP support is used, the corpus is accessed via regular tool calls in the inference loop. MCP server architecture does not change — the caller handles the difference. This is a Phase 6 concern.

- **D-13:** MCP tools exposed:
  - `get_topic(topic_id, level?)` — returns L3 wiki page for a topic, optionally a specific level band section
  - `list_sources(topic_id, type?)` — returns L2 summary entries tagged to this topic
  - `search_corpus(query, subject?, level?, type?)` — free text search across topic pages and source material
  - `get_experiments(topic_id, min_age?)` — returns age-gated experiments for a topic
  - `list_topics(subject?)` — lists all topic IDs, optionally filtered by subject (mirrors `services/curriculum.py subjects()`)

- **D-14:** MCP server reads from the filesystem. No DB required for v1. Index built at startup from `docs/corpus/wiki/index.md` and frontmatter of all L3 files. Search is simple keyword matching against content + tags — no vector embeddings in v1.

### CORPUS-04 / Phase 5 Integration

- **D-15:** Content packages for device sync (SYNC-03) draw from `docs/corpus/wiki/topics/` and `docs/corpus/wiki/experiments/`. The sync endpoint calls MCP tools (or reads directly from filesystem) to bundle relevant topic pages and experiments for a child's current focus KCs. This is the primary consumer of the corpus in Phase 5.

### Reading Level & Source Acquisition (added 2026-08-19, from edtech research)

- **D-16 (superseded — see below):** ~~Adopt a 29-level reading taxonomy (`aa, a–z, Z1, Z2`, modelled on Learning A-Z's public level system)~~ — replaced with UK Book Bands (D-16 revised, 2026-08-19): Adopt the **UK Book Bands** colour scale (Pink A, Pink B, Red, Yellow, Blue, Green, Orange, Turquoise, Purple, Gold, White, Lime, ...) as the `reading_level` frontmatter field on book-passage and levelled-text source material. Book Bands is a cross-publisher UK industry standard (also used by Oxford Reading Tree, Collins Big Cat, and Cambridge Reading Adventures) — not proprietary to any single publisher — and fits etutor's existing UK National Curriculum framing better than the US-oriented Learning A-Z taxonomy. This field is separate from the existing `bloom_entry`/`bloom_target`/`level` fields on curriculum topics — `reading_level` measures decoding/fluency difficulty of the *text*, not conceptual difficulty of the *topic*. A 100-level topic page can cite a `reading_level: Blue` passage if the passage is easy to decode but conceptually introductory. See `docs/wanted-books.md` §Levelled Reading Schemes for the Cambridge Reading Adventures calibration-reference note (rejected as a content source; UK Book Bands naming adopted from it).
- **D-17:** Add `decodability` tagging to levelled text source material for the emergent-reader band (ages 5–8): tag which phonics patterns a passage requires (`cvc`, `ccvc`, `digraph`, `cvce`, `vowel_team`, etc.) in frontmatter as `decodability_tags: []`. This is a differentiator vs Raz-Kids' meaning-cueing approach and aligns with the science-of-reading consensus.
- **D-18:** Primary open-license sources for levelled reading passages, in priority order:
  1. **ReadWorks** (readworks.org) — non-fiction + comprehension questions, Grade 1–12, some CC — highest priority, ships with question sets matching the pre/during/post scaffold
  2. **StoryWeaver** (storyweaver.org.in) — CC BY 4.0, 200,000+ levelled children's stories, multi-language — second priority, largest open volume
  3. **BookDash** (bookdash.org) — CC BY, illustrated picture books Level 1–5 — youngest band
  4. **African Storybook** (africanstorybook.org) — CC BY, Level 1–7, phonics-aware
  5. Calibre-Web library (192.168.0.25:8083) — for advanced/older band (300–400 level) content and public-domain classics, not emergent-reader levelled text
- **D-19:** Do NOT pursue Raz-Kids/Learning A-Z licensing or API integration — confirmed no public API and no realistic licensing path (private-equity-owned enterprise SaaS, no developer program found). Adopt only their non-proprietary structural patterns (level taxonomy naming, running-record accuracy thresholds, pre/during/post scaffold) — these are standard literacy-assessment practice, not their IP.
- **D-20:** Running record accuracy thresholds (standard literacy assessment benchmark, freely reusable) recorded as reference constants for future use: independent ≥96%, instructional 90–95%, frustration <90%. Not implemented as a feature in this phase — noted for Phase 5/6 oral reading assessment if the device adds speech-recognition-based reading practice.

<specifics>
## Specific Ideas

- **knowledgebase-template L0→L3 model** — adapt this structure exactly; see https://github.com/scottcowan/knowledgebase-template
- **Pedagogy over disclaimers** — historical/offensive content handled by teaching context first (colonialism, language change as curriculum topics), not warning labels
- **Permissive age gating** — prerequisites trump age hints; only genuinely dangerous physical activities have hard age locks (`flagged_dangerous: true`)
- **People pages** as cross-cutting reference: a historical figure (e.g. Marx, Darwin, Montessori) can appear on multiple topic pages; their people page is the canonical bio with all their linked topics
- **stdio MCP** is the right transport for v1; HTTP MCP is deferred until a non-Claude-Code consumer needs it
