## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser→/parent/* HTML views | All protected by require_parent_auth session cookie dep |
| /v1/sessions/* JSON API | Device-facing; NOT gated by parent cookie (per RESEARCH Pitfall 5); device uses X-Device-ID; separate auth concern |
| profile form POST body | Parent-submitted form data; child_id from URL path (not user-supplied in body) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-03-01 | Elevation of Privilege | All /parent/* HTML routes missing require_parent_auth | mitigate | Every new route in this plan adds `_: None = Depends(require_parent_auth)`; test_parent_views.py verifies unauthenticated redirects for each route |
| T-4-03-02 | Information Disclosure | IDOR — /parent/sessions/{id} returns turns for any session | mitigate | In v1 single-family mode, any authenticated parent owns all data — `require_parent_auth` is sufficient; document for future multi-tenant upgrade path |
| T-4-03-03 | Tampering | XSS via Jinja2 template variables (child name, turn text, interest tags) | mitigate | Jinja2 auto-escapes all `{{ }}` variable output by default; no `|safe` filter used on user-supplied content |
| T-4-03-04 | Information Disclosure | /v1/sessions/* device API exposes turn data without parent cookie | accept | Device API is intentionally open to device (CR-02 scope resolution per RESEARCH Pitfall 5 and PATTERNS.md lines 133-148); full IDOR closure for device path is Phase 5 scope |
| T-4-03-05 | Tampering | Profile form: reading_level set to arbitrary string | mitigate | Server validates reading_level is one of ["beginner", "developing", "fluent"] in POST /children/{child_id} before DB write; invalid values silently ignored (not stored) |
| T-4-03-SC | Tampering | slopcheck | accept | No new packages in this plan |
</threat_model>
